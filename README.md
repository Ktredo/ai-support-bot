# AI Support Bot (RAG + Self-Correction)

Пет-проект: AI-ассистент для службы поддержки, который ищет ответ в базе знаний и проверяет сам себя, прежде чем отправить ответ клиенту.

**Проблема:** обычные LLM хорошо отвечают на общие вопросы, но на конкретной базе знаний (регламенты, инструкции) начинают галлюцинировать — придумывать несуществующие законы, телефоны и сроки.

**Решение:** пайплайн ищет факты в базе знаний и прогоняет ответ через вторую модель-аудитор. Если аудитор находит выдуманный факт — ответ переписывается, а если не получается — выдается безопасная заглушка.

## ⚙️ Как это работает

1. **Triage:** модель читает вопрос клиента. Если клиент пишет эмоционально («ПОЧЕМУ ВЫ СПИСАЛИ ДЕНЬГИ?»), вопрос переформулируется в сухой поисковый запрос.
2. **Hybrid Search:** поиск по базе знаний через **Qdrant** (поиск по смыслу) + **BM25** (поиск по точным словам вроде «ст. 229-ФЗ»). Результаты объединяются алгоритмом RRF.
3. **Generation:** модель `mistral-nemo` (через Ollama) пишет ответ, опираясь на найденные факты и правила общения (Tone of Voice).
4. **Self-Correction:** модель `qwen2.5:7b` выступает аудитором и ищет в ответе выдуманные факты. До 2 попыток переписать ответ.

## ✨ Что реализовано

* **Разделение ответов:** бот выдает ответ клиенту и отдельную заметку для оператора (что произошло и что делать дальше).
* **Режимы:** `bank_support`, `pizza_guest`, `pizza_delivery`, `pizza_staff` — у каждого свои промпты и ToV.
* **Память диалога:** последние 6 реплик на клиента, `TTLCache` (1000 клиентов, 5 минут).
* **Пост-обработка:** регулярки вычищают маркдаун, списки и подписи, ответ обрезается до 2–4 предложений (логика — в `textutils.py`).
* **API и CLI:** FastAPI (`/chat`, `/health`, `/modes`) и интерактивный режим в консоли.

## 🛠 Стек технологий

* Python 3.12
* FastAPI + Uvicorn
* Ollama (локальный запуск LLM)
* Qdrant (векторная БД)
* SentenceTransformers (`intfloat/multilingual-e5-small`), rank_bm25
* pytest (тесты)

## 🚀 Как запустить

1. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
2. Установите Ollama и скачайте модели:
   ```bash
   ollama pull mistral-nemo
   ollama pull qwen2.5:7b
   ```
3. Создайте `.env` в корне проекта (пример — `.env.example`):
   ```
   OLLAMA_URL=http://127.0.0.1:11434/api/generate
   MODEL_NAME=mistral-nemo
   AUDITOR_MODEL=qwen2.5:7b
   ```
4. **База знаний:** все ответы бот ищет в `knowledge_base.txt` (формат «ВОПРОС: … / ОТВЕТ: …», блоки разделяются пустой строкой). Замените содержимое на свои данные.

Запуск:

```bash
# консольный режим
python main.py

# API (http://127.0.0.1:8000/docs)
uvicorn api:app --reload

# curl
curl -X POST http://127.0.0.1:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"client_question": "Почему списали деньги?", "mode": "bank_support"}'
```

Через Docker:

```bash
docker compose up --build
```

## 🧪 Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты API не требуют Ollama: `SupportSystem` подменяется заглушкой, поэтому проверяется контракт эндпоинтов (валидация режима, коды 200/422/500/503, передача аргументов в пайплайн).

## ⚠️ Известные ограничения

* Аудитор проверяет только часть фактов (названия, цены, состав, номера статей) — выдуманные описания процедур он пропускает.
* Triage иногда искажает смысл вопроса («почему списали» → «как вернуть»), и поиск уходит не туда.
* Коллекция Qdrant переиндексируется только когда она пуста: после правки `knowledge_base.txt` удалите `qdrant_db/`.
* Поиск не фильтрует по режиму: банковские и пиццерийные факты лежат в одной коллекции.
* При недоступности Ollama аудитор пропускает ответ (fail-open).

## 📁 Структура

| Файл | Что делает |
|---|---|
| `main.py` | CLI и оркестратор пайплайна |
| `api.py` | FastAPI-обёртка |
| `qdrant_rag.py` | Чанкинг, эмбеддинги, Qdrant + BM25 + RRF |
| `auditor.py` | Модель-аудитор |
| `prompts.py` | Промпты и режимы |
| `textutils.py` | Пост-обработка ответа (чистые функции) |
| `eval_tests.py` | Evals: прогон пайплайна + оценка судьей (1–10) |
| `tests/` | pytest-тесты |
